# Changelog

## [Unreleased]

### Added

- Encrypted-at-rest configuration content: every `Config.Content` value is now sealed with AES-256-GCM before it reaches the SQLite store. New `internal/crypto` package implementing the envelope (HKDF-SHA256 per-user subkey derivation with `salt=nil` and info string `tabby-sync/v1/user/{userID}`, AES-256-GCM with a freshly generated 12-byte random nonce, and a canonical 17-byte AAD: 1-byte `CryptoVersion` (`0x01`) || big-endian `int64` userID || big-endian `int64` configID). New `internal/keys` package providing two master-key providers behind a `Provider` interface: a `file` provider rooted at `${TABBY_SYNC_DATA_DIR}/master.key` that AUTO-GENERATES a fresh 32-byte key on first start (atomic temp+rename, file mode `0o600`, parent dir mode `0o700`, no path or key bytes ever logged), and an `env` provider that reads `TABBY_SYNC_MASTER_KEY` as 64 hex characters. New `internal/store/encrypted` wrapper sitting above `internal/store/sqlite` that satisfies a new `store.EncryptedStore` interface and is the single seam between the persistence layer and the cryptographic envelope; the underlying SQLite store stays oblivious to encryption (it sees opaque ciphertext+nonce blobs) so issue #6's contract did not need to change. The wrapper handles SQLite's autoincrement ID quirk via a two-step write (insert with placeholder AAD, re-encrypt under the canonical `(userID, configID)` AAD, UPDATE in place; rollback the orphan via DELETE if the second step fails). Decrypt failures (cross-user, cross-config, tampered ciphertext or nonce, wrong master key) surface as the bare `crypto.ErrDecrypt` sentinel UNWRAPPED so callers can use `errors.Is` without `strings.Contains`. `cli.runServe` loads the master key via `keys.LoadFromConfig` after `auth.LoadUsersFile` and BEFORE binding the listener, constructs `encrypted.New`, defers the wrapper's `Close`, zeroes the local master-key slice once the wrapper holds its defensive copy, and emits exactly one structured `master key loaded` log line carrying ONLY the provider name (no path, no key bytes, no length). All existing scrubPaths call sites now also strip the master.key path so a wrapped error from any layer stays redacted. The encrypted store is constructed and closed today but NOT yet plumbed into HTTP handlers (FIXME marker references issue #8). Adds a single new dependency `golang.org/x/crypto v0.31.0` (pure-Go, CGO-free) for the `hkdf` sub-package, and ships `docs/CRYPTO.md` (threat model, on-disk format, AAD layout, BACKUP imperative) cross-linked from `SECURITY.md`. **Losing the master key means losing access to all encrypted configs; back it up separately from the database, and re-back-up after every rotation** (#10).
- Bearer-token authentication. New `internal/auth` package: `users.yml` schema (`id`, `name`, `token_prefix`, `token_hash`, `disabled`), strict YAML loader using `KnownFields(true)`, in-memory `UserStore` with constant-time SHA-256 lookup (`crypto/subtle.ConstantTimeCompare` against the matched user's hash or a zero-hex sentinel on miss so timing does not leak map membership), atomic `Reload` that swaps snapshots without blocking in-flight `Lookup` calls, and a `Bearer` HTTP middleware that stashes the authenticated user on request context and returns a generic 401 on every failure path. The `Bearer` scheme prefix is matched case-insensitively per RFC 7235 §2.1. The middleware chain in `internal/server` now runs the authenticator on every route except a `GET` or `HEAD` request to the literal `/healthz` path, which keeps a route-aware bypass so liveness probes do not need an Authorization header (other methods to `/healthz` are still gated). `runServe` calls `auth.LoadUsersFile` immediately after opening the SQLite store and before binding the listener, so a missing or malformed users file fails fast with the on-disk path scrubbed out of the log line. No token plaintext, SHA-256 hash, or Authorization header value is ever logged. Adds a single new dependency `gopkg.in/yaml.v3 v3.0.1` (pure-Go, CGO-free) and ships `docs/users.yml.example`. `gopkg.in/check.v1` appears in `go.sum` as yaml.v3's test-only transitive; it is recorded for build reproducibility but is not compiled into the binary and was not separately authorised. Limitation: `UserStore.Reload` is API-only in this release; cli.runServe does NOT wire it to SIGHUP, an admin endpoint, or a file watcher, so an operator who edits `users.yml` on disk MUST restart the process to pick up the change. A follow-up issue will land a runtime trigger (#7).
- SQLite-backed `internal/store` layer: per-user `Config` CRUD interface (`CreateConfig`, `GetConfig`, `ListConfigsByUser`, `UpdateConfig`, `DeleteConfig`, `Close`), embedded migrations runner with a `schema_migrations` ledger, strict per-user row scoping that returns `store.ErrConfigNotFound` on cross-user access, and four pragmas applied at Open (`journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`, `synchronous=NORMAL`) verified after the DSN options are applied. Adds a single new dependency `modernc.org/sqlite v1.50.1` (pure-Go, CGO-free); the database file lives at `${TABBY_SYNC_DATA_DIR}/tabby-sync.db` and is opened by `runServe` before the listener binds (#6).
- HTTP middleware stack and server hardening: per-request `X-Request-Id` (with strict inbound allowlist), panic recovery with structured logging, JSON access log (excludes Authorization/Cookie/body), 1 MiB request body size cap (`middleware.DefaultMaxBodyBytes`), conservative security headers (`X-Content-Type-Options`, `Referrer-Policy`, `Cache-Control`, `Content-Security-Policy: frame-ancestors 'none'`, `X-Frame-Options: DENY`), `MaxHeaderBytes = 1 MiB`, and an `internal/auth.Middleware` placeholder contract with a no-op `auth.None()` constructor (#5).
- Initial Go project skeleton: `cmd/tabby-sync` entry point, `internal/{api,auth,config,server,store,store/sqlite,crypto,keys,version}` packages, `serve` / `version` / `help` subcommands, environment-driven configuration, slog structured logging, and a baseline `Makefile` (#4).
